# 🍄 木木的树洞

**慢慢说，也可以不说。**

木木住在一棵亮着小灯的树里。你是一只小香菇，随时可以来坐坐。它有点懒、有点倔，嘴上嫌麻烦，朋友真有事又很上心。

[直接去木木家坐坐](https://selinazy.github.io/mumu-treehole/)

## 同一个木木家，两种回复方式

公开演示与私人版共用 `public/index.html`、`public/chat.css` 和 `public/chat.js`。角色、场景、对话展示与回看、分饼干和靠着休息的互动都一样，不再维护两套聊天布局。

| | 公开演示 / 快速体验 | 私人本地版 |
|---|---|---|
| 剧情场景与角色互动 | 相同 | 相同 |
| 点击示例句 | 预写对话，可继续接话 | 交给模型回应 |
| 自由输入 | 通用示例，明确标注“未分析你的输入” | 根据近期对话生成回应 |
| 模型调用 | 无，不上传或分析输入 | 使用自己的 OpenAI API 项目 |
| API Key | 无填写入口、不需要密钥 | 仅在本机 `.env` 配置 |
| 本次聊天与草稿 | 当前标签页保存，与私人版隔离 | 当前标签页保存 |

公开版是互动体验展示，不是免费的在线 AI 服务。所有示例回复都有标记；演示脚本只匹配完整示例句，不会根据自由输入猜测情绪或触发玩笑动效。页面中的“关于这里”和燕来的小纸条可以查看说明。

## 快速体验

需要 **Node.js 22 或更高版本**，没有第三方运行依赖，不需要 `npm install`。

```sh
npm run demo
```

打开终端显示的地址，默认是 <http://127.0.0.1:8787/>。即使电脑已有密钥，这个命令也不会调用 API。也可以用静态服务器直接托管 `public/`；所有资源使用相对路径，支持 GitHub Pages 项目子目录。

- 点击开场示例句，或自由输入，体验当前说话人的台词与角色反应；点“回看”查看完整聊天。
- 拍长椅空位：小香菇拍椅子，木木从树屋走来坐下。
- 碰木木头顶的树苗：分一块饼干。
- 点小香菇：靠着木木休息，再点一次坐好；“想说话了”恢复对话。
- 点树门：木木回树屋，之后可以再次邀请。
- 输入框旁的小笔用于开始新聊天，确认后才清除本次聊天和草稿。

互动支持鼠标、触屏和键盘，尊重系统的减少动态效果设置。场景动作不调用 API，也不伪造聊天消息。

## 开启自己的真实回信

1. 在 [OpenAI API 平台](https://platform.openai.com/api-keys) 创建自己项目的密钥，确认项目有可用额度。
2. 复制配置模板：

   ```sh
   cp .env.example .env
   ```

3. 在本地编辑器中填写 `.env` 的 `OPENAI_API_KEY` 和 `OPENAI_MODEL`。模型需要支持 Responses API 与 Structured Outputs，具体可用模型以你的 API 项目为准。密钥不要放入网页、聊天、截图或 GitHub。
4. 启动：

   ```sh
   npm start
   ```

5. 打开 <http://127.0.0.1:8787/>。此时是同一个剧情聊天界面，顶部标明“私人版 · AI 回应”。原来的 `/visit/` 书签会自动跳转到这个入口。

Enter 发送，Shift + Enter 换行。等待回应时可继续写草稿，上一条结束后再发送。失败或取消后保留未接上的原话，可手动重试；已经发出的请求仍可能产生 API 用量。

修改 `.env` 后需重启。macOS 也可双击 `start-mumu.command`，保持启动窗口打开。脚本在 Node 支持时沿用已有的系统 HTTPS 代理，仅作用于当前进程，不改系统设置。

本次聊天与草稿使用 sessionStorage，刷新可恢复，关闭标签页后不保证保留。每次发送最近最多 10 轮已完成对话及本次输入，总上限 18,000 字符；不读取旧信，没有跨次聊天的长期记忆。

## 以前写的信

旧写信页保留在 `letters.html`。从燕来的小纸条可以进入，页面也提供返回聊天的入口。旧信和草稿仍使用原来的 localStorage，存储键未改，不会因这次界面更新而清空。

写信页的公开模式仍使用预写回信；私人模式仅在勾选希望回信并寄出时调用 API。旧信支持回看和删除，与当前聊天分开存储。

## 木木的性格

角色提示词在 `prompts/mumu.txt`，连续聊天与场景规则在 `prompts/visit.txt`，动作输出约定在 `prompts/reaction.txt`。

- 固定性格：喜欢清闲、讨厌无谓折腾，小事上会嘴硬，也会认错；有自己的偏好。
- 先接住情绪，和用户同队，敢吐槽具体的不合理行为，不编造别人的恶意。
- 同一个角色，随着聊天自然地一起烦、一起开心、接着玩、安静陪伴或认真帮忙，不按关键词切换人格。
- 普通闲聊短一点，不复述整段经过、不连续追问；明确求助时按需要展开。
- 不假装记得未提供的经历，不承诺排他关系，不做心理诊断或治疗。

公开演示不执行模型提示词，只展示独立的预写片段。真实聊天的效果取决于使用者配置的模型。

## 数据与边界

- 无分析追踪、无服务器数据库，不在应用日志记录聊天。服务器仅监听本机 `127.0.0.1`，校验浏览器来源、请求大小和并发。
- 静态公开版不会上传或分析聊天输入；本地演示模式的 API 路由也拒绝调用模型。
- 私人聊天将近期对话及提示词发送给 OpenAI，请求使用 `store: false`。这不等于提供方不保留任何数据，详见 [API 数据说明](https://developers.openai.com/api/docs/guides/your-data)。
- 本机 `.env` 被 Git 忽略。浏览器只收到模式和配置就绪状态，收不到密钥。
- 内容不跨设备同步；清除浏览器数据会丢失，同一浏览器的其他使用者也可能查看。这不是加密保险箱。
- 项目没有公开服务的用户认证与配额体系，请勿将私人后端直接暴露到公网。
- 尚未实现云端同步、匿名交流或付费功能。

## 发布与验证

```sh
npm run check
npm test
```

测试使用模拟模型，不消耗 API 额度，覆盖演示与真实 API 隔离、上下文校验、来源限制、错误处理、静态资源路径和演示对话行为。

GitHub Actions 的 **Publish demo** 工作流在推送 `main` 后检查并发布，**只部署 `public/`**，不读取 API Key、不需要 GitHub Secrets、不启动私人后端。GitHub Pages 的 Source 应设为 GitHub Actions。

```text
public/index.html       两版共用的剧情聊天入口
public/chat.css         共用场景与聊天样式
public/chat.js          共用互动逻辑，按配置选择回复来源
public/demo-chat.js     离线预写示例，不调用 API
public/config.js        静态部署默认为公开演示
public/letters.html     保留旧信访问的写信页
server.mjs              本地 API 与模式配置
prompts/                木木的性格、场景与动作规则
.env.example            不含密钥的配置模板
test/                   不调用真实 API 的测试
.github/workflows/      GitHub Pages 工作流
```

界面与角色使用 HTML/CSS 绘制，不依赖外部字体、图片服务或前端框架。
